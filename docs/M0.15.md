# OpenAudioOS M0.15

M0.15 keeps OpenAudioOS on its own internal AirPlay implementation path.

## Goal

Do not compile or depend on the previously tested third-party AirPlay project.

Instead, make our own simple implementation safer and more explicit:

- discovery
- RTSP listener
- OPTIONS handling
- path parsing
- `/fp-setup` diagnostics
- body length parsing
- first-byte capture
- adapter-based placeholder PCM path

## Important limitation

M0.15 still does not implement real FairPlay.

When iOS sends:

```text
POST /fp-setup
FPLY ...
```

OpenAudioOS logs it and returns a clean `501 Not Implemented`.

That is intentional. A fake FairPlay response would be unstable and misleading.

## Next milestone

M0.16 should implement the first real FairPlay response step only if we have a verified, legal, working byte-level description or our own compatible implementation.
